# NodeSeek auto

为 NodeSeek 准备的 Tampermonkey 脚本。核心能力是通过表单快速生成单机或多机交易帖的标题与 Markdown，减少重复填写，让配置信息更清晰、交易内容更易读；此外还提供抽奖配置与开奖跟踪、交易状态切换、回复楼层追踪、关键字过滤等日常功能。

## 安装

**[一键安装到 Tampermonkey（油猴）](https://raw.githubusercontent.com/wangjialiangsaa/NodeSeek_auto/main/NodeSeek%20Issue%20Templates.min.user.js)**

当前版本 **1.4.68**。安装后由本仓库 `main` 分支自动更新；[可读源码版](https://raw.githubusercontent.com/wangjialiangsaa/NodeSeek_auto/main/NodeSeek%20Issue%20Templates.user.js)也可直接安装。首次使用需先安装 Tampermonkey，点击链接后在油猴页面确认安装，刷新 NodeSeek 生效。

已安装旧版时，用此链接更新；如果另装过独立的“NodeSeek 楼中楼阅读”，请停用独立脚本，使用本整合版。

脚本在 NodeSeek 各页面提供对应功能：发帖与编辑页有“出🐔模板”“收🐔模板”和“🎁 抽奖配置”，帖子页有楼中楼、自动续页、固定回复栏、抽奖跟踪、交易状态与「我的回复」，列表页有关键字过滤。

## 界面

界面跟随 NodeSeek 的浅色 / 深色主题自动切换，无需额外设置。

个人信息统计栏内提供漏斗图标与“过滤”入口，位于左列底部，与等级、鸡腿、通知等项目保持相同的图标、字号和间距。点击后打开“过滤”面板，支持关键词、用户昵称以及屏蔽和高亮处理；原顶部导航和齿轮旁的入口已移至此处，已有规则继续使用。折叠与隐藏均直接移除匹配帖子在列表中的显示，不留提示条或“查看”按钮。

个人信息统计栏右列底部提供齿轮图标与“自动化”入口，和左侧“过滤”并排显示，沿用原栏的图标尺寸、字号和间距。点击可设置每日签到和抽奖帖自动回复，原有配置继续使用。

编辑栏只显示一个 **“🐔 工具”** 按钮，点击展开出鸡模板、粉色上传图片、计算器和收鸡模板。展开后保留原按钮的图标和颜色，点击空白处或按 Esc 收起。**“出🐔模板”**用于发布出售帖，**“收🐔模板”**用于发布收购帖，两者互不影响。

帖子回复栏支持 **Enter 发送、Shift + Enter 换行**，发送使用原站评论按钮。中文输入法选词和空白内容不会触发发送，长按回车不会重复发送；发帖和脚本设置表单保持原来的键盘操作。

楼主和各楼层昵称下方显示公开用户资料：等级、鸡腿、星辰、主题帖数、评论数和加入天数，楼中楼和下滑加载的新楼层同样支持。资料从 NodeSeek 官方用户空间接口读取，只为进入视野附近的用户加载，同一用户缓存 10 分钟并复用；最多同时查询两位用户。接口失败时保留原来的作者栏，不编造数据。可在油猴“功能开关 → 用户资料”关闭。

## 功能

### 图片上传

- “🐔 工具”菜单内，**“出🐔模板”**旁提供同尺寸的粉色 **“上传图片”** 按钮，支持一次选择多张图片。上传进度和重试入口显示在菜单内，上传时工具按钮显示忙碌提示。
- 在原生发帖、回复或私信编辑栏中按 **Ctrl+V** 粘贴截图 / 图片，即自动上传到官方 [NodeImage](https://www.nodeimage.com/) 并在光标处插入 Markdown；普通文字粘贴保持原样。
- 首次使用如提示未登录，点击“登录 NodeImage”完成 NodeSeek 授权，再回到原页点“重试”，无需手填 API Key。
- 上传中可继续编辑草稿；失败可重试，选中的原文会恢复。单张图片最大 100 MB，图片上传完成后再发布。

### 自动任务

从个人信息统计栏 **“自动化”**（“过滤”右侧）或油猴菜单 **“自动任务设置”** 打开设置。

- **每日自动签到**默认开启：登录并打开 NodeSeek 时检查签到，北京时间跨天后继续检查，领取固定奖励。关闭网页时不运行，可在设置中关闭。
- **抽奖帖自动回复**默认关闭，回复语句留空。先填写自定义语句，再勾选开启并保存；进入帖子后自动检测楼主正文内指向本帖、尚未到期的官方 `/lucky?post=…&time=…&mode=view` 抽奖链接，发送保存的语句，无需再点击抽奖链接。
- 已回复、自己发起的抽奖和已有草稿会跳过；不遍历其它帖子。按账号与帖子记录结果，多标签页共用任务锁，避免重复提交。
- 发送前逐页核实**当前帖子**的回复；发现你的旧回复会跳过，不再因个人历史评论超过 10 页而无法触发。分页加载失败、登录验证或页面信息不完整时跳过，并显示原因。
- 回复通过站点原生“发布评论”按钮提交。提交后如无法确认结果，设置中会提示检查网页，不会自动再次发送。浏览器不支持任务锁时保留手动操作。

### 出🐔模板

- 支持厂商、型号、CPU、内存、硬盘、带宽、流量等配置的选择、匹配和自由新增
- 支持单机、多机书签编辑与统一标题生成
- 支持剩余价值计算、续费金额人民币换算和实时汇率；可选择是否导出价值卡片
- 支持预出总价与溢价二选一校验及价格预览
- 支持填写 NodeSeek / TQ 地址，以及常用标签快捷选择
- TG 地址本地缓存：填写一次后可自动回填
- 支持文本和表格两种 Markdown 导出格式
- 支持新帖与编辑已有帖子；重新编辑时会把正文还原成表单，方便继续调整

### 收🐔模板

- 填写目标机器的厂商、型号、CPU、内存、硬盘、带宽、流量，同样支持候选项与自由输入
- 内置机器配置库：可搜索已登记配置，选中型号后自动回填整套配置
- 支持续费金额与周期，便于对方判断机器价值
- 收购方式可选：剩余价值收、剩余价值折收、剩余价值加价收、剩余价值减额收、总价收、带价聊
- 支持交易标签（原邮 / 改邮、包中介 / 不包中介、先机后款 / 先款后机、站内私信）与自定义标签
- 标题同样支持字段选择与排序，可填写常用备注并自动带入
- 填写 TG 联系方式，方便对方联系

### 抽奖

- 发帖时可一键生成抽奖信息并写进正文，开奖链接自动指向正确的帖子地址
- 帖子页跟踪自己发起与参与过的抽奖，已到开奖时间提醒你公布名单、中奖后提醒你去查看
- 开奖后一键公布中奖名单：自动改写帖子标题并追加 @ 中奖人
- 详见[抽奖](#抽奖)与[抽奖跟踪](#抽奖跟踪)

### 帖子辅助

- **楼中楼阅读**：采用 Reddit 风格的层级细线与圆形加减按钮，把父评论和子回复排列在一起。点击减号收起该分支的全部后代，保留父评论正文，显示“另外 N 条回复”；点击加号展开。支持多层分支独立收起，可切换“楼中楼 / 引用 / 原始”。
- **下滑自动加载**：接近评论区底部自动接入下一页、去除重复置顶评论，直到末页；从中间页打开时继续加载之后的分页。
- **固定回复栏**：原生回复框固定在底部，可展开 / 收起，保留草稿和原生发布按钮；评论的回复、引用可直接展开它。
- **交易状态**：自己发布的交易帖在楼层旁提供「已出 / 不出了」（出售帖）或「已收 / 不收了」（收购帖）按钮，一点即可切换标题状态
- **我的回复**：在帖子页列出自己在该帖回复过的楼层，可直接跳转；列表页则标记出回复过的帖子
- **关键字过滤**：按关键字隐藏列表页里不想看的帖子

楼中楼、自动续页和固定回复栏默认开启，可在油猴菜单的“功能开关 → 楼中楼阅读”即时关闭或恢复。“原始”只切换评论排列，续页和固定栏仍保留。未加载的父评论可以跳转或预览。1.4.68 兼容论坛编码后的评论数据，让下滑加载的评论能继续使用原生点赞、鸡腿等菜单；站点数据或组件无法复用时，仍提供“引用 / 回复 / 原页操作”，可在原页完成操作。加载失败后，等待几秒继续下滑即可重试。

楼中楼模式隐藏右上角楼层编号，对话默认折叠。在个人统计栏的“自动化 → 楼中楼默认折叠”中取消勾选并保存，即可改为默认展开。修改后立即应用当前页面，新打开的帖子也沿用选择；仅保存其它设置不会重置手动展开或收起的分支。

同一页面内，新回复和下滑续页会沿用各分支的收起状态，并更新回复数量；新出现的分支按默认设置显示。展开父分支后，原先收起的子分支仍保持收起。切换“引用 / 原始”会显示全部已加载评论并恢复楼层编号，回到“楼中楼”恢复分支状态。定位新回复、“我的回复”或楼层链接时，会先展开目标所在的祖先分支。原生评论节点、回复和菜单按钮继续保留。

回复后论坛重建评论列表时，会保留此前自动加载的评论。提交回复引起刷新或跳到末页时，同一标签页会恢复刚才已加载的分页及手动收起状态，再定位新回复，避免前面的对话消失。恢复失败保留当前评论，可继续下滑重试；普通打开某一分页仍从该页向后加载。

阅读进度针对当前已加载的评论。正文开头的本帖较早 `#楼层` 链接，以及句中、句末相邻的站内 `@用户名 #楼层` 回复链接，可用于判断父子关系；支持连续多层回复。普通 `@用户名`、正文中单独提及的楼层链接、引用块和代码不用于归组。更多说明见[楼中楼整合说明](docs/threaded-reading.md)。

## 抽奖

发帖页「发布」按钮旁有独立的「🎁 抽奖配置」入口，只对当前页面这一次发布生效，重新打开发帖页就要重新填：

- 设置开奖时间（默认 24 小时后）、奖品数量、起始楼层与楼层去重；开奖时间旁实时显示还剩多久
- 参与方式支持任意回复、包含回复、固定回复，并可叠加点赞、鸡腿等互动条件
- 参与方式不是任意回复时，可勾选「不满足条件时顺延至下一位」
- 抽奖信息可以写在正文末尾或开头，参与方式、开奖时间、中奖人数可逐项决定是否展示
- 标题默认 `# 🎁 抽奖信息`，支持 Markdown，留空则不写标题行
- 弹窗内实时预览将要写进正文的内容

点「保存本次抽奖」会把这块模板插入正文，你可以在编辑器里自行审阅、调整位置或补充说明。之后照常用 NodeSeek 的「发布」按钮发帖，发布成功后脚本会自动把开奖链接补成指向这篇帖子的正确地址，其余内容一律不动，并记下这次抽奖供后续跟踪。

几点行为约定：重复保存会替换上一次插入的那一块，不会堆叠；如果正文里那块被手动改过、或刷新后旧配置已失效，保存时会二次弹窗让你选择「保留编辑器内容」还是「强制覆盖」（强制覆盖会删掉旧的那块再按本次配置插入）。想把抽奖撤掉，直接把正文里那块模板删掉即可。

抽奖链接使用 NodeSeek 官方 [抽奖程序](https://www.nodeseek.com/lucky) 的格式。NodeSeek 的抽奖工具仅按楼层计算，点赞、鸡腿和回复内容只能写进说明，需要自行核对。

## 抽奖跟踪

帖子页右侧面板会多出「抽奖」与「中奖」两个条目，数字分别是待办数量和未读中奖数：

| 条目 | 计数条件 |
| --- | --- |
| 抽奖 | 我发起的抽奖中，已到开奖时间、有中奖名单但正文还没 @ 全部中奖人的帖子数 |
| 中奖 | 我参与过的抽奖中，已开奖且我在名单里、还没点开看过的帖子数 |

点开条目可以看到对应列表：「我发起的抽奖」按帖子列出状态、中奖人名单和开奖链接；「中奖记录」只列我中奖的帖子。

**跟踪范围**

- **我发起的抽奖**：不限于用「抽奖配置」发布的帖子。手动发起、后来编辑补上开奖链接的帖子，同样会被跟踪。
- **我参与的抽奖**：在别人的抽奖贴里回复并发布，就记为参与。开奖后没中奖的记录会自动清理，不会留在列表里。

**公布中奖名单**

已到开奖时间后，帖子 #0 楼层旁会出现「公布中奖名单」按钮，点击后一次性完成两件事：把标题改成 `【已开奖】原标题`，并在正文末尾追加中奖名单（`@名字 [#楼层](链接) 恭喜中奖🎁`）。

**列表管理**

「我发起的抽奖」与「中奖记录」的每条记录右侧都有「删除」按钮。其中「待公布」的记录删除前会二次确认——它代表一件还没做完的事，删掉就没有提醒入口了；未开奖的记录不提供删除（结果还没出，删了就追踪不到）。

**其它约定**

- 中奖名单直接取 NodeSeek 官方抽奖页的结果，脚本不自行计算中奖人
- 帖子开奖后会持续留意名单变化，例如楼主后来才补 @ 中奖人
- 记录保存在本机浏览器，不随账号同步

## 配置共建

机器型号和市场变化很快，因此脚本提供了可选的配置共建机制。

勾选出🐔模板里的“授权检查配置并提示”后，生成出售帖时会检查当前机器配置；配置库里没有的会被登记为新的可复用配置。若不希望提交，取消勾选即可，脚本不会检查或上报机器信息。

![配置提交选项](docs/images/catalog-submission.png)

已登记的配置会记录贡献者，方便查看自己贡献过的机器配置。

![已登记配置](docs/images/catalog-contributions.png)

填写型号时，可根据输入内容搜索已登记配置；选中后会自动回填厂商、型号、CPU、内存、硬盘、带宽、流量、续费周期和续费金额，并展示贡献者昵称。

![配置自动回填](docs/images/catalog-autofill.png)

## 开发

推荐 Node.js 24；测试依赖要求 Node.js 20.19+、22.13+ 或 24+。

```sh
npm ci
npm run build
npm test
node --check 'NodeSeek Issue Templates.user.js'
node --check 'NodeSeek Issue Templates.min.user.js'
git diff --check
```

源码位于 `src/`，本地厂商图标在 `assets/vendors/`。根目录的 `NodeSeek Issue Templates.user.js` 与 `NodeSeek Issue Templates.min.user.js` 分别是可读版和压缩版构建产物，不直接编辑；修改源码后执行构建命令。

GitHub Actions 会在推送和 Pull Request 时重新构建、运行 DOM 整合与配置库测试，并验证构建产物没有未提交差异。推送 `v*` 标签会自动创建 GitHub Release 并附带两份脚本。一键安装与自动更新直接使用本仓库 `main` 上的压缩版，不依赖 Release。

楼中楼回归测试覆盖多层分支收起、动态回复与续页、模式切换、定位展开、原生节点与事件保留，以及回复后的阅读范围恢复。原生点赞与鸡腿菜单使用模拟组件验证，不发送真实评论或进行真实互动；此前 Reddit 风格样式的浏览器视觉预览受权限限制。验证范围见[楼中楼整合说明](docs/threaded-reading.md)。

## 共享配置服务

服务端位于 [`worker/`](worker/README.md)，部署到 Cloudflare Workers + D1。部署后将 Worker 地址填入 [`src/config.js`](src/config.js) 的 `MACHINE_CATALOG_API_URL`，再构建并发布 userscript。
